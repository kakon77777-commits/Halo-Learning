# Halo Learning v0.4.0 — B02 Reversible Renderer Retention Validation

Status: verification in progress

## Root cause

Real Chromium reports the renderer's own lifecycle mutations with a finer topology than the original mutation journal described:

1. `replaceWith(...children)` first removes child text nodes from the owned wrapper, then replaces that wrapper in its parent;
2. `Node.normalize()` mutates the surviving text node once per non-empty adjacent text node merged, while empty text nodes are only removed;
3. a standalone non-empty text node produces no normalization mutation.

The previous journal omitted the wrapper-side removal, collapsed multiple character-data records into one, and over-declared a mutation for a standalone text node. That produced two retained renderer records plus one pending expected descriptor even though the DOM itself restored correctly.

## Minimal repair

The renderer mutation journal now mirrors Chromium/DOM normalization topology without weakening the sanitizer or changing reversible DOM semantics. The focused unit fixture was updated to encode the observed normative record sequence.
