## Causal chain and repairs

### 1. Synthetic renderer key event did not exercise `chrome.commands`

The original installed-browser test used Playwright `page.keyboard.press('Alt+Shift+H')` as if it were a browser/OS accelerator. Diagnostic run `32996197405` showed that Chromium registered the command and selected the correct active tab, but the synthetic renderer-level key event left no content receiver and no panel.

A headed Chromium/Xvfb diagnostic changed only the test input boundary to an OS-level X11 shortcut driven by `xdotool`.

Run `32998966552`, job `98275440514`: **PASS**. The native shortcut made `HALO_STATUS` reachable, observed one selection read and one renderer call, and produced exactly one panel.

### 2. The test waited for visibility on the zero-size Shadow DOM host

The renderer intentionally keeps `[data-halo-owned="panel"]` as a protected zero-size host (`width: 0`, `height: 0`, `overflow: visible`). The visible UI is the shadow `.halo-core-panel`.

The B05 E2E was corrected so visual readiness waits target the visible shadow panel, while host count/detachment assertions continue to measure lifecycle ownership.

Relevant repair: `b8125b55baef77f8cc4c69b028c470fa392a391b`.

### 3. Outside-click geometry attempted to click through the visible panel

Once the real panel was visible, the fixture's nominal `#outside` control could be covered by the panel. Playwright correctly refused to click through it.

The E2E now computes a real viewport point outside the shadow panel bounding rectangle and clicks that point. No product pointer behavior was weakened and `force: true` was not used.

Relevant repair: `6faec1cdc78a3e74fef921bc6488674550661f3b`.

### 4. Main-world SPA `pushState()` was invisible to the isolated content world

A route-cleanup diagnostic demonstrated a genuine product lifecycle defect. After main-world `history.pushState()`:

- the URL changed;
- the panel remained connected and visible;
- `HALO_STATUS` did not advance its policy/renderer counters;
- route cleanup had not executed.

The cause was realm isolation: `DynamicDomController` patched `history.pushState/replaceState` in the extension content script's isolated world, while the page SPA invoked History API in the main world.

A fresh Chromium causal probe proved that `navigation.currententrychange` in the extension `ISOLATED` world observes the main-world same-document History transition. Run `33002339450`, job `98287123767`: **PASS**; the probe changed from `count: 0` to `count: 1` and reported the exact `/route-two` URL.

The production repair adds `apps/extension/src/shared/navigation-route-bridge.js` and injects it immediately after `dynamic-dom-controller.js` and before `content.js`. The bridge:

- subscribes to `navigation.currententrychange` when available;
- forwards the transition to the canonical `controller.routeChanged()` path;
- removes its listener during controller cleanup;
- represents listener-removal failure as cleanup debt (`navigation-listener`);
- deactivates a retained listener before cleanup retry so it cannot resurrect route work;
- is guarded against repeated browser-global wrapping.

Production repair commit: `52f558c3343b1c77f1fd2c0a36c4837744ca98eb`.

No manifest permissions, host permissions, site-policy rules, trigger-controller FSM semantics, service-worker command semantics, or renderer semantics were broadened.

### 5. Duplicate-panel measurement raced an asynchronous popup selection action

After SPA cleanup was fixed, the canonical E2E reached the repeated-injection / duplicate-panel assertion. Two preceding popup actions used `popup.click()` and immediately sent Escape. The popup event listener is asynchronous, while Playwright's click completion does not await the Promise returned inside the DOM event handler. A late panel open could therefore enter the observer window and inflate host-add counts.

The B05 native test harness now waits for the content-page shadow panel to become visible before forwarding Escape. Extension/popup pages skip this settling wait; if no panel is pending, Escape retains raw keyboard semantics. This is test synchronization only.

Relevant repair: `72b69042d7fc562bceaf28e24917784b434a9037`.
