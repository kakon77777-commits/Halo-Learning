## Root cause

Real Chromium exposes `window.chrome` as a browser-owned non-configurable global. Fresh descriptor reproduction returned:

```json
{"configurable":false,"enumerable":true,"writable":true,"valueType":"object"}
```

The old second sentence-pipeline browser case attempted to replace that object with:

```text
Object.defineProperty(globalThis, 'chrome', ...)
```

and reproduced `TypeError: Cannot redefine property: chrome`.

The runtime sub-property is a viable fixture seam: defining `window.chrome.runtime` on the existing namespace succeeds without changing the `window.chrome` descriptor. The fixture now preserves the real browser namespace and injects only its scoped `runtime` mock.

A second initialization defect was exposed after removing the first exception: the browser fixture loaded `settings.js` without its browser-global dependency `site-policy.js`. The test now loads `site-policy.js` before `settings.js`.

## Verification

A real Chromium seam check verified the `window.chrome` descriptor is byte-for-byte equivalent before and after fixture setup while `chrome.runtime.sendMessage`, `HaloSettings`, `HaloSentencePipeline`, and `HaloRuntimeScheduler` are all available.

Relevant Node/unit regression:

```text
71 tests
71 pass
0 fail
```

The container's system Chromium is governed by an administrator URL policy and rejects loopback navigation with `ERR_BLOCKED_BY_ADMINISTRATOR`; this is outside the repository and occurs before application code. The historical canonical CI failure had already established that the first sentence browser subtest passed and the second reached the `window.chrome` redefinition failure. No Chromium weakening flag or production semantic change was introduced.

## Scope

Only browser fixture initialization changed. Production extension/runtime semantics and shared browser harness behavior are unchanged.
