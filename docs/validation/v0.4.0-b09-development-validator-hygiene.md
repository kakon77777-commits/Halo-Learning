# Halo Learning v0.4.0 — B09 Development Validator Hygiene Evidence

- Branch: `integration/v0.4.0-final-convergence`
- Blocker: B09
- Final result: **resolved**
- Final causal repair commit: `ec6e086ecff56a11b55d67f8b2306e86fe2d89f7`
- Final verification date: 2026-08-26

## 1. Root cause

The v0.4 development validator intentionally begins with a strict Git source-hygiene gate. The release workflow generated three deterministic release outputs inside the source checkout before development validation:

- `dist/halo-learning-magic-hand-v0.4.0.zip`
- `dist/halo-learning-v0.4.0-package-manifest.json`
- `releases/Halo_Learning_v0.4.0_Browser_Runtime_UX_Release.zip`

It also wrote release-evidence logs below `evidence/architect-release/`. These generated paths made `git status --porcelain --untracked-files=all` non-empty, so the workflow invalidated its own development-validation precondition.

The exact pre-repair reproduction was:

```text
pre_package_git_status: clean
post_package_git_status:
  ?? dist/halo-learning-magic-hand-v0.4.0.zip
  ?? dist/halo-learning-v0.4.0-package-manifest.json
  ?? releases/Halo_Learning_v0.4.0_Browser_Runtime_UX_Release.zip
validator_stage: source hygiene
validator_exit: 1
error: development Git worktree is not clean
```

## 2. Interim ordering repair was insufficient

The earlier B09 commits `753df4f8...` / `2b1c3188...` moved the development validator before package generation. That removed the package-output dirtiness in isolation, but it was not the final causal closure:

1. shell redirection created `evidence/architect-release/development-validator.log` before `npm run validate` started, so the real workflow could still dirty the checkout before `source hygiene`;
2. the development validator also owns `release package integrity`, so permanently running it before package generation would eventually leave that gate without its required artifacts after the other blockers were removed.

The final repair therefore preserves both source hygiene and package-integrity availability instead of merely moving the first observed failure.

## 3. Final repair

The final B09 repair keeps the existing validator contract unchanged.

- `.gitignore` now names only the three canonical generated v0.4 release outputs above.
- release-evidence logs and hash records are staged under `/tmp/halo-v040-release-evidence`.
- deterministic packaging runs before the development validator, so release package-integrity artifacts exist when required.
- the workflow asserts `git status --porcelain --untracked-files=all` is empty after packaging and both before and after development validation.
- package integrity still verifies exact inventory, source bytes, and SHA-256 values; ignored build artifacts are not accepted merely because Git ignores them.
- no `git clean -fdx`, force reset, generated-artifact commit, hygiene bypass, or runtime change is used.
