## Root cause

Fresh mutation tracing proved the third-party child insertion was not lost in the observer or sanitizer:

1. the `childList` mutation was observed;
2. operation-scoped sanitation retained the externally authored record;
3. invalidation selected the original paragraph root;
4. renderer cleanup retained the third-party child and its identity;
5. fresh text extraction saw exactly `The initial system! learns.`.

The failure occurred after extraction. The newly inserted `!` was treated as a normal sentence terminator, so the scheduler received two semantic records — `The initial system!` and `learns.` — and the frozen browser predicate could never observe one semantic request item containing `The initial system! learns.`.

## RED

`tests/b01-token-child-insertion.test.js` constructs the minimal aggregate:

```text
The initial system + <i>!</i> +  learns.
```

Before the repair the records were:

```json
["The initial system!", "learns."]
```

instead of the required single record.

## Minimal repair

`sentence-pipeline.js` now exposes an optional `isSentenceTerminatorProtected(node, offset, character)` seam. Protected terminators are masked only in the segmentation copy of the aggregate; UTF-16 offsets and the returned sentence text continue to use the original source bytes.

`token-child-continuity.js` supplies that seam without public DOM markers. It:

- receives the existing private `isHaloOwned` predicate from the dynamic-DOM controller configuration;
- records externally authored child additions into an owned token in a `WeakMap` keyed by node identity;
- protects punctuation only while the retained child is moved by renderer cleanup into the recorded destination parent;
- stops protecting it if the node later moves elsewhere.

The bridge is injected immediately after `dynamic-dom-controller.js` and before `reversible-renderer.js`. No content-script public ownership contract or ordinary sentence-boundary rule is weakened.
