## Causal round 2 — service-worker target replacement + runtime lifetime

The second bounded repair strengthened the reload boundary from worker-version observation to explicit service-worker target replacement.

Commits:

- `524a3ebce789514aeb83cfa42016ac615c51550c` — `test: define B06 service-worker target replacement contract`
- `c39676a3312861227f74f15259a754c8de91f73e` — `fix: observe MV3 reload through target replacement`
- `f74ba0fc2161c08dcce9eb8da8227f754ba8f162` — `fix: prove MV3 reload by target and runtime lifetime`

The accepted observer contract:

1. enable CDP target discovery;
2. snapshot the current exact-script `service_worker` target;
3. install `Target.targetCreated` and `Target.targetDestroyed` listeners **before** the reload action;
4. require destruction of the old target;
5. require creation of a distinct same-script service-worker target;
6. only after that lifecycle boundary, probe `HALO_DICTIONARY_STATUS`;
7. require `mode === "ready"` and a `networkActivity.lifetimeId` distinct from the pre-reload lifetime.

The helper handles either event ordering: the replacement target may be observed before or after destruction of the old target, but it resolves only when both facts are true.
